# CoralNPU 与在线内存的联合仿真

本项目只保留 CoralNPU 作为计算和访存发起端。生产入口是仓库根目录的
`./run.sh run`，完整验收入口是 `./run.sh test`。公开配置位于 `config/`。

## 1. 实际运行链路

```text
CoralNPU CoreMiniAxi RTL（Verilator）
  ⇄ 原生异步 C ABI
  ⇄ AXI128/256 字节通道适配与 AXI256 五通道
  ⇄ Axi2Flit ⇄ UcieAouAdapter ⇄ 双向 UcieLink
  ⇄ AouTarget ⇄ MemSimBackend ⇄ 在线 mem_sim
```

独立主程序在 `simulation/main.cc`，只链接本工程独立构建的一套
Accellera SystemC。全局时间分辨率为 1 fs。设备库不包含第二套 SystemC。
主程序自动装载本地 TCM 中的 ELF 并启动 NPU；外部存储读写全部经过上面的链路。

## 2. 源码职责

以下路径相对于仓库根目录：

| 实现 | 职责 |
|---|---|
| `integration/coralnpu/coralnpu_native.h/.cc` | RTL 包装器的创建、ELF 装载、步进、异步请求与响应 |
| `third_party/coralnpu/hw_sim/core_mini_axi_wrapper.h` | RTL 请求回调、请求容量反压和返回队列 |
| `simulation/axi_master.hh/.cc` | 原生请求到 AXI256 的字节通道映射、有限在途队列、响应顺序 |
| `simulation/axi_demo.cc` | 五通道接线、复位、VCD 与握手稳定性检查 |
| `simulation/aou_backend.cc` | AXI2Flit、UCIe 和存储端的联合拓扑 |
| `simulation/memsim_backend.hh/.cc` | 存储请求拆分、有界排队、内存时间步进、真实数据返回 |
| `mem_sim/integration/online.h/.cpp` | 在线内存 C ABI 与原生控制器/行为 PHY |
| `scripts/verify.py` | 将 NPU 请求、AXI、内存数据与独立计算公式逐笔核对 |

## 3. 接口与时序

CoralNPU 原生请求包含 16 字节数据和字节掩码。AXI256 适配器按地址低位把数据
放入对应的 32 字节总线通道，保留 WSTRB；读响应从对应通道提取 16 字节返回 RTL。
AXI AW/W/AR/B/R 分别进行真实握手，并记录 VCD 和 CSV。

原生适配层当前支持 CoreMiniAxi 使用的单拍、非独占 INCR 访问；未知地址、
不支持的 burst 和重复响应会报错。通用桥本身的多拍能力不代表 NPU 原生接口
已经支持多拍。`axi.outstanding` 限制在途请求，满时向 RTL 包装器反压；
同原生 ID、同读写方向的响应按请求顺序交付。

设备时钟与 AXI 时钟由同一 SystemC 调度器推进。在线 mem_sim 的
`period_fs` 决定原生内存 tick 到全局时间的映射。内存返回后才允许相应的
AXI 响应和 NPU 完成回调，因此慢内存会改变 NPU 执行周期。
`memory.scale` 是内存时间轴敏感度参数，不能解释为另一种实际器件速度档。

启动装载只访问本地 TCM；mailbox 属于设备控制状态。外部窗口没有私有 RAM
回退或预填充旁路，数据由 NPU 通过在线链路写入，再读取、计算和验证。

## 4. 配置与命令

在仓库根目录运行：

```bash
./run.sh setup
./run.sh build
./run.sh check
./run.sh run
./run.sh run --scale 4
./run.sh run --replay
./run.sh run --architecture config/architectures/backpressure.json
./run.sh run --benchmark config/benchmarks/strided.json
./run.sh test
```

`check` 只检查可加载性和依赖隔离；计算与链路是否通过以 `run` / `test`
生成的 `summary.json` 为准。每次使用新的结果目录，保留失败证据。
具体字段与可修改范围见 [配置说明](../../config/README.md)。

## 5. 验收证据与边界

每个用例保留 `resolved.json`、`environment.json`、`completion.json`、
`npu_requests.csv`、`transactions.csv`、`axi_events.csv`、`axi_wave.vcd`、
两端 Flit、内存请求/返回、DRAM 命令、DFI、最终镜像以及分块 HTML。
NPU 请求及响应按序号关联 AXI 事务，计算字节按独立公式检查；原始 VCD
与 CSV 交叉核对，不能用退出码或文件存在代替这些检查。

完整验收覆盖默认、慢内存、CRC 重放、另一规模/跨步和反压场景，
并执行 mem_sim 原生测试、在线 C ABI 测试及损坏证据拒绝检查。
实际执行结果见 [ACCEPTANCE.md](../../ACCEPTANCE.md)。

本链路使用 RTL 生成的 NPU 模型与行为级 UCIe/内存 PHY；原生回调是有界事务
适配层，不能声称 NPU 管脚与 AXI256 逐线直连。默认 benchmark 是存储读写及
运算自检，完整神经网络、跨设备缓存一致性和物理层合规性不在当前验收范围。
`SimpleBurstMemory` 与 AXI BFM 仅用于底层组件测试，不能替代上述生产链路。
